亚马逊云科技最近推出了 Lambda Web Functions，让开发者能够直接在 Lambda 上运行使用 Express 和 Hono 等框架构建的 Node.js Web 应用，并支持并发请求和流式响应。

根据 Lambda Web Functions 文档，新函数支持并发 HTTP 请求和流式响应。其计费依据是活跃 CPU 时间和内存，而不是等待下游服务期间的 CPU 时间。多区域路由会将请求发送到距离最近的区域，而一个已经预热的执行环境可以同时处理多个并发请求，从而显著减少冷启动。现有 Lambda 函数现在被称为 Lambda Event Functions，无须进行任何改动。亚马逊云科技高级解决方案架构师 Micah Walter 总结了它的优势，以及它为何能够消除这些复杂性：

你可以使用 Express、Hono、Fastify、Next.js 或任何 Node.js 框架构建一个监听标准端口的服务器，通过一条命令进行部署，随后 Lambda 会自动处理扩缩容、多区域分发和活跃 CPU 计费。无须适配器，无须管理基础设施，也不会被框架锁定。

端点默认使用 Lambda 提供的域名。如果需要使用自定义域名、边缘缓存或 AWS WAF，开发者可以在前端部署 Amazon CloudFront，并将 Lambda Web Functions 作为源站。

Lambda Web Functions 面向 HTTP 工作负载，包括全栈 Web 应用、REST 和 GraphQL API，以及可以独立扩展的微服务。它还支持服务器端渲染和流式响应，例如大语言模型的增量输出，而无须单独的托管层。

Lambda Web Functions 目前仅支持 Node.js；包括 Python、Java 和 .NET 在内的其他语言仍可通过传统 Lambda 函数使用。今年早些时候，亚马逊云科技还推出了 Lambda MicroVM，为运行不可信代码或用户生成代码提供隔离的有状态沙箱环境，并允许客户自行管理生命周期。

在《探索如何使用 AWS Lambda Web Functions 构建 Web 应用》一文中，Julian Wood、Kim Wendt 和 Samrat Karak 构建了一个示例应用，展示单个执行环境如何同时处理多个请求，以及应用程序如何服务全球用户。他们总结道：

Lambda Web Functions 无须适配层，即可将无服务器运维模型带入 Web 应用。你只需编写一个标准 Node.js HTTP 服务器，通过一条命令或 CloudFormation 进行部署，就能获得一个可扩展、按使用量计费的 HTTPS 端点，并内置全球路由。

Reddit 和 Hacker News 上的社区反响总体积极，讨论重点包括更简单的编程模型和并发请求支持。不过，讨论也提出了有关 Python 支持，以及该服务与现有替代方案有何区别的问题。用户 magnetik79 评论：

这是一次重大更新——也很高兴看到一个不完全围绕 AI 打磨的功能。☺️ 看起来很棒的地方在于：许多工作负载现在可以完全绕过 API Gateway（……）这彻底改变了目前 Lambda 的 HTTP 编程模型——现在不再是一次调用对应一个请求，你可能需要开始关注同步和互斥锁问题。

亚马逊云科技首席开发者布道师 Eric Johnson 在《为什么我对 AWS Lambda Web Functions 感到兴奋》一文中强调，Lambda Web Functions 无须修改即可运行标准 HTTP 服务器和框架，并通过一个托管端点支持 REST、服务器发送事件、流式响应、RPC、Webhook 和 IAM 身份验证。

亚马逊云科技并不是唯一提供这种模式的云服务商：Google Cloud Run 和 Azure Container Apps 也支持无须适配层的 Web 应用、缩容至零和可配置并发，因此适合具有间歇性或突发流量的工作负载。

Lambda Web Functions 的定价基于活跃 CPU 时间和内存使用量，对于需要花费较多时间等待数据库或 API 的工作负载，可能有助于降低成本。内存则按照执行环境的整个生命周期计费。这种模式可能适合服务器端渲染、API 后端和流式 AI 推理等 I/O 密集型工作负载。该服务目前已在五个区域推出：北弗吉尼亚、俄亥俄、俄勒冈、东京和爱尔兰。
