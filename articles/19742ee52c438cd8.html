请参考早期《弹弹堂》的回合制玩法，制作一款可在浏览器里玩的 3D 对战游戏。先把一局游戏做完整：从菜单进入，支持单人训练、1v1 人机和同机双人，能够走位、瞄准、发射、命中、结算并重开。保留原版看风向、调角度、蓄力发射、打人和破坏地形的乐趣；在此基础上把场景做成真正有厚度和前后层次的 3D 沙盘，而不是一张贴着人物的平面背景。

【地图与胜负】

先制作一张浮空岛地图：两侧是有厚度的草地与岩层，中间用一座可以炸断的薄木桥连接；岛上有缓坡、薄边和低平台，背景可以加入风车、灯塔和远山，但不要遮住人物、弹道与落点。玩家既可以攻击对手扣血，也可以炸掉脚下的地形，让对手掉进坑里或坠出地图。有坑底时角色应能落地并继续行动；地面打穿后，即使还有生命值也会坠落出局。生命耗尽和跌落出界分别给出清楚的结算原因。

【操作与对局】

提供左右移动、调节发射角度、按住空格蓄力并松手发射；风向和风力会影响弹道。首版可以以 12 秒为一回合、12°—82° 为可调角度、约 1.12 秒蓄满为起点，再根据实际试玩调整。提供普通弹、破土弹和纸飞机：普通弹首次碰撞后自动爆开，可以命中角色并削地；破土弹直接伤害较低但削地范围更大；纸飞机用于改变站位或从坑底脱困，要有明确的次数或冷却提示。角色、弹道、地形碰撞和 AI 使用同一套规则。暂停或窗口失焦时冻结计时、飞行和 AI，恢复后不要补发之前按住的操作。

【角色、行动与数值】

可从每人 100 点生命、100 点行动体力起步，每移动 1 个游戏单位消耗 20 点体力。普通弹直击可先按 32 点伤害、范围伤害最高 20 点、削地半径 0.75 配置；破土弹每局次数受限，消耗 35 点体力，直击可先按 16 点、削地半径 1.05 配置。纸飞机消耗体力并占用行动，落点必须是角色确实能站立的位置。以上都是便于测试的初值，应统一放到配置中，而不是散落在画面或动画脚本里。

回合顺序需要可解释。可用累计行动时间实现：瞄准耗时、移动距离和道具各自增加下一次行动的等待；消耗较多时，对手有机会连续行动。保留教学用的固定交替模式，并清楚显示下一位行动者。达到行动上限时先比存活人数，再比剩余生命，相同则平局；重开后恢复地形和状态，并交换先手。AI 与玩家共用风向、道具、落点和地形规则，要会识别薄桥、坑底与自身坠落风险，而不是直接读取一个虚假的命中结果。

【地形与命中】

让可见地形和真正的碰撞、支撑判定使用同一份可修改的数据。炮弹命中时按实际接触点结算伤害和削地；连续打同一位置，坑应该继续变深、相邻坑可以打通，后续弹体可以穿过已经挖空的地方。角色失去脚下支撑时进入下落：下面有有效平台就落稳，没有支撑就继续下落，不能用一块看不见的地板把角色接住。角色、地形、爆炸、血条和伤害数字由同一事件驱动，不要出现看起来炸到了、实际没命中的情况。

地图可以用可修改的地形网格表示，单个格子同时决定可削地形、空洞与不可破坏部分。地形被击中后，先更新占用数据，再同步画面切面、角色脚下支撑、弹道、小地图与 AI 读取的版本。多名角色同时受到影响时，先处理所有人的下落和淘汰，再判断胜负和换手。训练场应能分别复现打出有底凹坑、继续打穿坑底、炸断薄桥以及后续炮弹穿过缺口。

【参考与 UI/UX】

先看早期《弹弹堂》的战斗截图和实况，逐个观察开局、走位、看风、调角度、蓄力、发射、换手和结算；再参考《Worms W.M.D》的回合计时、弹体跟拍和镜头回位。用同一张地图、同一个瞄准局面做两套确实不同的界面：一套把风向、角度、力度和上次落点集中在屏幕边上，一套把部分信息放在角色附近。把两版都放进真实 3D 对局里比较，检查弹体跟拍时读数是否出画、界面有没有挡住弹道，再确定最终方案。

玩家进场后应能立刻看清当前行动者、风向、角度、力度、生命值、体力和剩余道具。第一发打偏后，要能根据上次角度、力度、风和实际落点修正下一发。命中、削地、落坑、坠落、回合切换与胜负分别有可辨认的反馈；暂停、失焦、重开、同机换手也要正常。

【美术、建模与动作】

先比较几种真正不同的美术方向。可以从分层透视纸景学习前中后景，从中国皮影学习人物轮廓与动作辨识，从浮世绘观察风如何通过旗帜和飞叶表现；把这些观察转化成实际构图，不要只换一组配色。使用 Seedream 生成场景方案、角色站姿、前后景、地形切面、队伍徽记、道具和特效素材，挑选后真正接入游戏。主角、装备和需要多角度观察的道具可用 Tripo 或 Blender 制作。

设计两套轮廓、服饰和队伍配色容易区分的原创 Q 版角色，角色使用真实骨骼；分别覆盖待机、走位、蓄力、发射、受击、下落、着陆和胜负动作。武器、炮弹和纸飞机独立成件，换装备后手上的模型和局内道具要一起变化。模型先在 Blender 检查朝向、脚底、权重和持握位置，再放进游戏试走斜坡、换装备和实际开炮；弹体离手、命中与爆炸特效必须对齐。制作草地、岩层、木桥断面、云层、风向装饰、菜单、图标和结算画面时保持统一的造型与材质。

镜头从轻俯的侧向 3D 对战视角出发：既能看清人物与高抛弹道，也能看见岛屿的前后厚度、桥面与被炸开的切面。瞄准时可以推近，弹体飞行时跟随并适当拉远，随后回到能够辨认双方的对局画面；结算时分别照顾胜方和败方。可使用普通弹、破土弹和纸飞机的不同轮廓、尾迹、碎片和短音效，但特效不能遮住落点和危险边界。

【开发与验收】

先做可完成一局的灰盒，把操作、弹道、破地、落坑和胜负打通，再接入角色、动画、场景、美术与 HUD。用浏览器真实开局，至少依次验证：第一发射偏、依据上次落点修正、直接命中、连续挖坑、炸断木桥、有底落坑、无底坠落、暂停恢复、结算和重开；1v1 人机与同机双人都要走完。保留修前修后的同场景截图或正常速度录像，发现遮挡、脚底悬空、握持错位、弹道和特效不一致时继续修。正式验证还要覆盖：HP 清零与坠出地图是两种不同淘汰；一发炮弹只结算一次命中和伤害；脚底仍有支撑时不误判坠落；弹体飞过已经挖空的位置不会撞上原地形；视口缩小时 HUD 不挡住角色和落点。记录地图版本、随机种子、每次行动的角度、力度、风、命中与地形变化，保证同一局能够复盘。交付可运行的游戏、完整源工程、启动说明、素材来源及实际验证结果。

请参考《3D 炸弹兄妹》和泡泡堂式的走位、放置与开路玩法，制作一款可在浏览器里玩的 3D 游戏。先做一个能够从开局、清场走到胜负结算并重新开始的房间，再扩展敌人、道具与不同波次。场景、角色和可交互物体都要有真正的 3D 体积，玩家需要看得清脚下、危险范围、障碍物和能撤离的路线。

【场景与一局游戏】

先搭建一间约 14×10 游戏单位的房间：玩家从一侧入场，另一侧放传送门，房间里有不能破坏的固定建筑和可以炸开的箱体或外壳，至少保留两条从出生点通向主要区域的路线。镜头从斜俯视开始，允许拖动、拉近和拉远；当墙体挡住角色时，让遮挡层降低或变透明，确保角色脚下、门洞和危险边界始终可见。固定建筑与可破坏障碍要在轮廓、材质和碰撞上区分，破坏箱体后应真实改变路径并掉落可拾取的物品。

用传送门和波次组织对局：先让一类追逐敌人迫使玩家走位，再加入会提前提示方向的冲刺敌人。可先按三波设计，分别用 3 只追逐敌人、3 只追逐加 1 只冲刺、4 只追逐加 2 只冲刺作为起点，清空一波后给下一波短预警。玩家拥有 3 格护盾，可拾取修复件和能量补给；全部敌人清空后胜利，护盾耗尽或超时后失败，结算页可以重开。数值要集中配置，根据真实试玩再调整。

两侧可以用机柜或建筑做永久掩体，通道之间摆放可破坏外壳；固定掉落可以包含能量晶片和修复件。两类敌人应有不同的轮廓、速度与动作：追逐敌人持续施压，冲刺敌人先预告方向再移动。敌人从可看见的安全区域或传送门入场，暂停时波次、倒计时、敌人与弹体一并冻结。满能量后可增加一次有独立动作和范围反馈的角色脉冲，拾取和击败敌人能补充能量。

【放置、投掷与爆炸】

角色能向当前方向移动、放置或投掷弹体。轻点执行快速投掷，长按时显示清楚的抛物线和落点，松手才出手；放置要让手部动作和弹体接触地面的时刻对齐。提供普通弹和遥控弹两种类型，并在 HUD 标明当前选择与剩余槽位：普通弹落地后开始倒计时并自动触发，遥控弹落地就绪后由玩家主动引爆。可以从普通弹 1.8 秒倒计时、遥控弹落地约 0.35 秒后就绪、最多同时存在 2 颗开始调试。切换弹种只影响下一次放置或投掷，已经放出的弹体必须保持原有规则。

爆炸范围、预警、障碍遮挡和实际伤害要一致：硬障碍能够阻挡，软箱被击中后破坏，范围内敌人和玩家按规则受击；支持已落地弹体之间的连锁，但一颗弹体只能结算一次。敌人冲刺前有可见预告，玩家受击时有短暂无敌反馈。用不同的形状、计时环、灯光和动作区分定时弹、遥控弹、已就绪状态与即将生效的危险，不能只靠颜色。

遥控弹可以在落地后等待一个短暂的就绪时间，按下引爆键时先显示可感知的短预告，再实际触发；若一直未使用，应有明确的回收和槽位恢复规则。空中、已落地、倒计时、遥控就绪和即将爆开是不同状态。两类弹共享槽位时，飞在空中的弹体也要占位；发生连锁时取消旧的倒计时或引爆安排，防止一颗弹重复触发。危险预告与硬障碍遮挡必须跟真实判定一致，修复件与能量道具拾取后要即时反馈到状态和界面。

【参考与 UI/UX】

先观察《3D 炸弹兄妹》的房间布局、角色比例、传送门、计时和操作；再对照《超级炸弹人 R 2》如何区分硬墙、可破坏物、连锁与逃生路线，以及《Captain Toad: Treasure Tracker》在斜俯视画面里如何避免前景遮住角色脚下。把观察结果转成具体设计：哪些信息固定在屏幕边，哪些倒计时、危险范围和预警应该显示在对应的弹体或地面旁。

在同一个最拥挤的战斗画面里做两套不同方案：同时出现一颗即将触发的普通弹、一颗已经就绪的遥控弹、一只准备冲刺的敌人和一个可以逃走的转角。把两版放进真实对局，按正常速度和缩小后的画面比较，选出让玩家更快看懂哪颗先爆、危险到哪里、往哪里撤的一版。配装界面要能看见角色和当前装备，切换后模型与下一局的实际效果同步；失败时能看出受击和失败原因。

【美术、建模与动作】

先比较至少两套有实质差异的画面方向。可以参考剧场几何的人物剪影、玩具展厅的色块与形状，也可以借用模拟仪器的外壳、开口和刻度组织房间；选择一种能让角色、弹体、危险和逃生路线读得清楚的方向。用 Seedream 生成房间构图、角色完整站姿、敌人、两种弹体、传送门、地砖、护盾和补给图标、特效与界面素材，挑选后实际放进游戏，而不是把概念图直接贴成游戏画面。

用 Tripo 或 Blender 制作主角、需要真实遮挡的场景物件、敌人和道具，主角绑定骨骼并覆盖待机、跑动、放置、抛投、受击和倒下。角色模型先检查朝向、脚底、手部和骨骼，再进实际机位检查跑动、转身、持物、放置、抛出与受击。弹体离手、落地、开始倒计时和爆炸特效必须与真实状态同步。用同一套造型、材质和光照做墙体、地砖、箱体、传送门、角色、HUD 和结算画面。

人物动作至少有待机、跑动、放置、抛投、受击、失败与能量动作。用真实骨骼驱动动作，角色在场景中的位移仍由游戏控制器负责，避免动画和控制器各走一次。主角手部、弹体挂点、抛物线、落点和爆炸范围要在正常速度的实机画面里逐帧对齐；角色和不同装备各用独立的可编辑资产。追逐敌人、冲刺敌人、定时弹、遥控弹、固定建筑和软箱在缩小画面里仍要靠轮廓与动作区分。

【开发与验收】

先做灰盒验证移动、放弹、抛弹、自动触发、遥控触发、破坏箱体、拾取、敌人、胜负、暂停与重开；再把角色、场景、动作、声音和界面逐步接入，并完成完整一局。实际测试普通弹在空中时尚未计时、落地后会自动触发；遥控弹未就绪时无法引爆、就绪后响应；切换弹种不改变场上已有弹体；两颗弹同时存在时不能无限放置；连锁不重复结算。试玩中检查被障碍卡住、抛投落点不准、危险提示被遮挡和爆炸掉帧等问题，录下修前修后的同一场景。验收还要分别录一次完整胜利、一次受击失败并重开；检查放置失败会给提示且不错误占槽，投出的弹在空中不会提前倒计时，暂停前后的引信与敌人状态一致，重开会清空上一局的计时、敌人和掉落。检查多弹连锁时每颗弹和每次受击只结算一次；在门洞、木箱和固定建筑附近实测撤离路径，确认玩家不会被看不见的碰撞卡住。导出包含操作说明、可编辑素材、完整源工程、可运行构建和实际验证记录的成品。

03 技术架构解读：2.4T 底座怎么做到“更强还更省”？

看完实测，再来把的技术架构拆开聊透：同为，为什么它的每个 token 激活参数降到了，能力反而全面上涨？Qwen4-Max2.4T 总参数、1M 上下文71B（比上代减少约 25%）

核心在于它围绕稀疏 MoE 的做了三处很巧的架构优化：长度、深度和容量

第一，GDN + Qwen Sparse Attention（QSA）混合注意力。

标准 Softmax Attention 在长序列下，计算量和 KV Cache 占用会随长度平方级增长，上下文拉到 1M 时开销很大。

从架构图左侧主干可以看到，Qwen4-Max 采用了的 4 层循环结构：前 3 层用 Gated DeltaNet（GDN）维护固定大小的状态矩阵，将历史信息持续压缩更新进去，用恒定开销保住长程记忆；第 4 层用 QSA（稀疏注意力），通过轻量索引器以 block（块）为单位筛选相关上下文做精细计算。先压状态、再按块检索，在保住 1M 上下文精度的同时，把长序列的计算和索引开销降了下来。3 层 GDN Layer + 1 层 QSA Layer

第二，Gated Residual（GR，门控残差）。

传统残差把所有历史层输出累加到单一隐藏状态里，模型层数做深、参数上到 2.4T 后，跨层信息容易退化，训练也容易波动。

Qwen4-Max 把残差流扩展成，在进入 Attention/GDN 和 MoE 前后加入了GR Read与GR Write动态读写门控，控制每一层怎么跨分支读取和写回特征。这直接稳住了超大规模训练：4 条并行分支（Expanded Residual）2.4T 规模下，预训练全程平稳，loss 持续下降，从头到尾没有出现过一次 loss spike。

第三，328B N-gram Embedding（Layer 2 only）。

输入 token 除了走常规词表嵌入（Vocabulary Embedding），还单独拉了一路直接注入第 2 层。它根据局部上下文做O(1)查表，引入局部 token 模式的额外表示，在不增加 MoE 专家激活计算量的前提下，用很小的额外开销扩展了模型容量。N-gram Embedding Layer

这三处改动合在一起，在知识（4.86）、代码（1.67）、问答（2.94）和 STEM（2.70）四类内部评测中，Qwen4-Max-Base 的每字节比特数（BPB，越低越好）在五个参评模型里全部最低，比同为 2.4T 的 Qwen3.8-Max-Base。下降了约 5%–13%

架构底层的提效，落到日常使用上也很不错：

一是思考 Token 更省，推理效率更高。

Work360 上，Qwen4-Max 光是 High 档的得分就已经超过了上代 Qwen3.8-Max 的 Xhigh 档，同档位下 Xhigh 和 High 的 token 消耗分别减少约；Terminal-Bench 4.0 上分别减少约。（PS：正式版默认 High 档，日常够用；做复杂前端或游戏可按需切 xhigh 档）。24% 和 35%48% 和 49%

二是 API 全面降价，隐式缓存价格压得很低。

输入，输出，而，价格远低于海外主流模型。¥10 / 百万 tokens¥30 / 百万 tokens缓存命中只要 ¥0.5 / 百万 tokens

做大型工程或 Agent 任务时，项目代码、历史上下文和系统提示词会在多轮修改里反复带上，大量输入都在命中缓存。缓存降到 5 毛钱后，长任务账单少了一大截：Work360 评测里，单任务平均费用从 26.58 元降到了 11.16 元，降幅达到 58%。
