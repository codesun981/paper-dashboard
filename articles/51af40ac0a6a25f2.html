今天，百度文心 5.5 Flash Preview 正式发布，这已是文心在一周之内的第三次出牌。

11月5日，基座模型文心 5.5 Flash Base开源；


11月9日，首次披露 RSI 进展，发布 ERNIE Evolve；


11月11日，文心 5.5 Flash Preview 发布。

一周内连续三次出牌，这在文心历史上并不多见。三次动作环环相扣，从基座模型、RSI 探索到 Preview 模型，逐步展现出百度基础模型业务的新方向。

在外界长期的印象里，文心的处境有些微妙：启动够早，积累不少，存在感却不够高。在大模型竞争的坐标里，文心始终没能达到相应的预期。

今年7月，1997年出生的复旦大学博士孙天祥加入百度，出任基础模型研发部（BMU）负责人，同时进入百度模型委员会（BMC）。他曾是国产初代类ChatGPT开源大模型MOSS的主导者，也创过业。外界期待他接手基础模型业务后的第一份答卷。本周的三连击，或许算是这张答卷的一部分。

这次发布的文心 5.5 Flash Preview，重点放在了效率、成本和开源上。目前模型已上线千帆平台，Web端与API同步开放。官方表示，模型权重将于11月25日前采用Apache 2.0许可证面向全球开源社区发布。

在明天百度世界2026上，关于模型的更多信息也将得到披露。

先从榜单看起。文心 5.5 Flash Preview 在 Terminal-Bench 4.0、DeepSWE v1.1、AutomationBench、APEX-Agents 1.1、DRACO、SpreadsheetBench V2、OfficeQA Pro V2、Agents' Last Exam共8项基准测试中，取得了AutomationBench和SpreadsheetBench V2 两项第一；在纳入对比的模型中，DeepSWE、APEX-Agents、DRACO、OfficeQA Pro V2 四项测试位列第二，其余项目也进入前列。

百度官方对这份成绩的描述是，“取得了具有竞争力的得分”，措辞相当克制。

榜单位置之外，能力版图的规划、实测过程中的工程细节，更能说明一款模型的实际成色。

按照官方口径，文心 5.5 Flash Preview  主要在四个方向升级：编程、3D建模、知识工作和内容创作。编程方向使用了超过1400万个可执行代码任务和多种Agent框架的执行轨迹进行训练；3D建模针对Blender、CAD等工具做了专项训练；知识工作后训练覆盖金融、法律等领域的30万个工作空间和1000万份文件；内容创作方向适配上千项Skill，构建了超过15万个创作环境，官方口径累计成片约5300分钟。

雷峰网(公众号：雷峰网)AI科技评论在第一时间上手测试了文心 5.5 Flash Preview的游戏开发能力。

你是一支由资深游戏制作人、游戏设计师、2D 美术总监、角色动画师、音乐设计师和游戏工程师组成的独立游戏团队。请开发一款受到《节奏天国》玩法理念启发的原创 2D 节奏游戏《砰砰退件局！》（PUNCH! RETURN!）


游戏的目标不是实现一个能按节拍出拳的程序 Demo，而是制作一段完整的、可交互的、充满生命力的卡通音乐喜剧。


整个场景必须像一个真实存在的荒诞卡通世界：不只有玩家和发货机器人，还有周围不断出现的小角色、各自独立的动作、对玩家成功或失败的反应、不断变化的环境、突如其来的乱入事件，以及最终所有角色共同参与的高潮演出。

以下是文心 5.5 Flash Preview在本次测试中的表现，游戏顺利完成了角色逐步登场、节拍判定与结算演出等核心环节。经多轮生成，总耗时约7分32秒，最终得到可运行版本。

这次测试一定程度上体现了文心 5.5 Flash Preview对高度复合型需求的应对能力，同时考察了该模型的审美、音乐节奏感、画面编排和动画制作能力，代码侧还要有大量事件的正确触发。以角色状态系统为例，如果状态机写得不好，角色在连续击打失败后就可能无法从紧张状态中恢复，进而波及整个场景的连锁反馈。

单一案例不能完全说明模型的稳定产出水平，但这类“一份文档、多个系统”的长需求题目，本身就是对编程能力最苛刻的考法之一。

官方博客中演示案例覆盖视频编排、游戏开发和3D建模等方向，其中游戏开发是最有分量的一块。

游戏开发的代表案例是《云岫行》：

一款第三人称东方武侠游戏，场景设定在云雾缭绕的张家界石峰与崖顶古寺，基于Unreal Engine 5.8构建。整个任务历时11小时，模型把跨越多代UE引擎的素材合入同一个UE5.8工程，用C++完整实现游戏。

试玩中发现的人物位置悬空、跑动方向不一致、摄影机位置错位等视觉问题，被模型逐一转换成可测量的代码测试问题，再通过不断完备的测试驱动项目迭代。“把视觉问题翻译成测试”，意味着模型建立了一套自我验证的闭环，这比一次性生成可运行代码更接近真实开发，也正是长周期开发任务里最难自动化的环节。

官方还披露了更大规模的案例：基于完整游戏策划方案，模型构建了近百款手机小游戏，覆盖弹幕射击、肉鸽、塔防、竞速、卡牌RPG、城建经营、物理解谜和互动叙事八个品类，其中24款重点作品横跨Cocos、Unity、LayaAir、PixiJS与原生Canvas 2D等多种技术栈，多数采用规则层与表现层分离的确定性模拟，并通过机器人模拟、状态空间搜索和关卡回放自动验证可解性与数值平衡——工程化验证的思路，与《云岫行》一脉相承。

《鹈鹕测试》是一支117秒的2D动画短片：

ERNIE 5.5 Flash Preview 用 Python 从零写出一部 116 秒的 2D 动画短片。一只白鹈鹕骑着自行车，从公元前 4000 年的撒哈拉岩画一路骑进大模型时代的代码编辑器，穿越 20 种艺术风格，最后登上“第 21 号鹈鹕发布会”。全片由上万行代码驱动，每一帧都用 Pycairo 矢量绘制，再由 NumPy 和 Pillow 做后期处理。同一只参数化鹈鹕在 20 个场景里化身汉画像石拓片、爪哇皮影、示波器光线和 8-bit 像素；换场时画面像胶片一样整格拉过，鹈鹕始终连贯地骑过画框接缝。

《星月夜》一场直接在梵高原作上让漩涡星空随踏频扭动。配乐精选 22 段录音，从金贝鼓、古琴、加美兰到马里奥主题，由模型编写的剪辑脚本按画面切换点逐场对齐。部分场景的背景由 ERNIE 5.5 Flash Preview 调用生图工具完成：唐代白描、清明上河图、莫卧儿细密画三场的静态底图都出自生图工具，ERNIE 5.5 Flash Preview 再在底图上用代码叠加会动的人物、落花与水纹。概念设计来自 Bilibili 创作者 @近步抱告_。

这道题的出题思路值得琢磨。视频生成竞赛里，单帧画面质量已经被卷得很高，真正的难点在跨场景一致性和节奏控制。同一只鹈鹕穿越20种风格而不失形态，一定程度体现了长程状态管理能力。

而在237秒的官方展示片里，模型围绕“地球要是也有个环”这个命题，连续完成查资源、写剧本、设计分镜、生成画面四道工序。官方披露的数字显示，完成一条片子，模型连续工作一到两个小时，工具调用中位数约170次，其间自己检查结果、发现问题并修正。

3D方向的两个案例都基于Blender完成：

其一，两个基于文心5.5Flash Preview的智能体使用Blender Python API分工协作：一个负责机场，自主检索地图平台的布局矢量数据，下载植物、车辆与地面服务设备等授权资产，通过参数化建模构建航站楼及飞行区；


另一个负责飞机，通过截面放样与模块化装配构建机身、机翼。随后两个工程统一尺度、位置与镜头，编排动画，用Cycles/OptiX GPU分帧渲染和FFmpeg合成视频。

其二，模型自主检索法隆寺的布局与建筑结构参考，逐步构建建筑群，细化到逐层收分、梁柱支承与层叠屋瓦，公开授权的佛像扫描与植物资产被融入场景，表面细节由PBR贴图与程序化节点材质共同完成。

两个案例的共同点在于：模型被放进了“检索—建模—渲染—合成”的完整流水线，而非单点执行一条建模指令。双智能体之间的任务拆分与协同，也让案例超出了单模型能力的范畴。

上文的游戏和视频案例都是长程任务：连续工作一到两个小时、工具调用中位数约170次、11小时的完整工程迭代。这类任务对推理速度的消耗远超日常问答，“快”在其中有实际意义。

对多数用户来说，更直观的数字是这一条：千帆API单用户推理速度超过200 tokens/s，约合每秒150个以上的汉字。生成速度到了这个量级，输出基本追得上阅读，等待感会显著降低。

官方对“快”的解释是一套系统的技术设计，可以拆成三层看。

第一层是参数的使用方式。文心 5.5 Flash Preview总参数量2800亿，每个token只激活140亿。在当前的稀疏配置中算比较激进一档。总参数决定模型的知识容量，激活参数才决定每个token的实际计算成本。2800亿参数更像常备库存，每生成一个token，只调用其中的一小部分。

第二层是显存。1M tokens的上下文如果每一层都做全量注意力，显存开销会大到无法落地。混合稀疏注意力就是对这个问题的回答：43层中，37层把历史每128个token压缩为一条缓存条目，保留全局视野；剩下6层保留逐token访问历史的能力，配合稀疏选取。效果是KV cache的占用大幅下降，长文本里的细节检索能力仍然保留。

第三层是推理阶段的加速。FP4把专家权重的存储压到4比特，直接节省显存带宽；ECHO则让主干网络的最后一层在预测下一个token之外兼任预测后续token的工作，这层同时充当投机解码的草稿模型——先猜后验，几乎不增加参数就换来提速。

三层设计指向同一个目标：用更少的激活参数交付够用的智能，把速度拉起来、成本再降下来。这也是“Flash”这个命名的行业惯例——比起单点极限，效率档产品线的核心逻辑更强调能力、速度、成本的平衡。

百度这次同步放出了完整的技术博客和模型架构图

定价方面，API每百万Token输入忙时2元、闲时1元，输出忙时8元、闲时4元，目前限时五折——折后，闲时输入0.5元、输出2元。在同参数规模的模型中，这是具备一定竞争力的价格。

换算一下更直观：一百万token约合六十万到八十万汉字。以模型支持的最长上下文为例，把一个100万token的窗口整个填满，折后的输入成本不到一元。

效率设计为文心 5.5 Flash Preview的低价打开空间：每个token只激活140亿参数，FP4压缩专家权重，推理成本已经被架构压了下来。

开源方面，模型权重将于11月25日前以Apache 2.0许可证面向全球开源社区发布，支持SGLang和vLLM部署。对开发者而言，这意味着拉取即可运行，商用没有协议负担。另外，今天文心 5.5 Flash Preview 的 API 已上线千帆平台。

值得一提的是，在实测和价格热议之外，有一条容易被忽略的消息：

文心 5.5 Flash Preview的部分推理优化工作，由百度11月9日披露的自动研究系统ERNIE Evolve完成：在昆仑芯P800的低时延场景上，ERNIE Evolve连续探索约168小时，把生成速度做到基线的623.6%；确定性推理吞吐提升至基线的133.7%，平均每个token的生成时间缩短26%，精度未降。

AI参与优化AI，眼下还处在早期，单次优化也说明不了全貌。但它指向的事实说明，模型之间的竞争，正在从参数规模的比拼，延伸到研发迭代效率的比拼。

一周之内三次动作，加上一份很有诚意的定价，百度文心这轮进攻的轮廓已经清晰：绕开正面战场，先在效率、价格和开源三个维度同时落子。

显而易见的是，今年的模型竞争正在分层：旗舰模型卷榜单上限，效率档模型卷成本曲线，文心选择的是后者。这条赛道今年格外拥挤，定价、演示和单次实测都只是入场券，能否转化为开发者的调用量，才是下一阶段的分野。

另一个值得记录的行业变化是：视频编排和游戏开发正在成为模型发布的新展台。这类任务不依赖跑分，产出可以进入工作流程，正在构成榜单之外的第二条战线。文心把长板放在这两个场景，是顺着行业节奏出牌，也让自己最容易被看见。

把时间线拉长看，这段口碑承压的日子，恰好也是文心埋头进步、低调追赶的时期。业界仍然对百度文心有所期待，期待它能追上有着丰厚技术积累的那个自己。在漫长的蛰伏期之后，它还会交出怎样的答卷？AI科技评论也将持续关注。
