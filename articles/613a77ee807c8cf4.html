Neon来了。(虎嗅注：Neon本意是氖，元素周期表第10位，稀有气体；高电压和低压氖气发光，也就是霓虹)


北京时间凌晨谷歌发布了Gemini 4家族新成员Gemini 4 Neon，既氩、碳、氢之后的又一个“元素”模型——一个兼具能力、速度与成本的性价比之作。


短短五周，谷歌接连向公众推出四款Gemini 4模型，密集上新引发了大家对AI自进化升级模型可能性的联想。以及，另一个讨论是，照这个速度下去，马上就要发到铀和钚了。


不敢想，这会是一个什么震惊瘫坐级别的模型。当然，模型还是不建议名字取得太大，否则容易压不住。



社交媒体上，Neon 收到的好评主要集中在视觉效果和速度上。有用户觉得，它还原前端组件动效的表现很出色。在一些对比测试中，Neon 比重量级模型更快完成了生成任务，有人直接把它称作“Opus 平替”。


批评声里，有人觉得 Neon 最终交出来的东西有些平淡，但更多吐槽则集中在谷歌编程工具Antigravity 的工具使用体验上。


看看跑分


照例先来个省流版本。


  • 能力接近旗舰，重点是更快完成复杂任务。 Google 将 Neon 定位在 Carbon 和 Hydrogen 之间，面向复杂编程、知识工作和科学研究；Carbon 仍负责最难、需要长时间推理的任务，Neon 并非全面替代旗舰。

  • 速度是主要长处之一。 Artificial Analysis 测得，Neon 的输出速度约为每秒 110 token，Carbon 约为 57 token。不过，输出更快不等于所有任务都能快一倍，实际效果仍取决于任务。

  • 办公、研究和编程是主要用途。 按官方介绍，Neon 可以综合处理文档、表格、图片和音视频，整理研究简报；在 Antigravity 中，还能完成代码仓库级修改、调试和重构，并与 Hydrogen 分工，由 Neon 规划、Hydrogen 执行。

  • 定价处于中间档，但暂时比促销旗舰贵。 Neon 的 API 输入、输出分别为每百万 token 3 美元和 15 美元，缓存输入为 0.15 美元。输入、输出单价均为 Hydrogen 的两倍，比 Carbon 12 月起的正式价低 25%；但比 Carbon 截至 11 月 30 日的促销价高 50%。

  • 应用内使用需要付费订阅，API 则按量收费。 Google 正向 AI Pro、Ultra 用户开放 Gemini 应用和 Antigravity 中的 Neon；开发者可通过付费 API 接入，支持 100 万 token 上下文，思考 token 计入输出费用。


再展开看看跑分。


单看跑分，Neon 已经接近旗舰水平了。但Google 这次更想强调的，是三个字——性价比。


在第三方机构 Artificial Analysis 的综合智能指数中，Neon 拿到61分，发布时排名第三，仅次于 Claude Fable 5.2 和 GPT-6.2 Astra，略高于 Carbon。



编程是 Neon 的突出长处。它在 Artificial Analysis 编码 Agent 指数中排名第一。按 Google 的介绍，Neon 不只生成代码片段，还能处理跨文件调试、重构和定点修改；在 Antigravity 中，它也可以负责规划，让多个 Hydrogen 子 Agent 分头执行。不过，在部分命令行和代码测试中，Opus 仍略占优势。



办公方面，Neon 更强调整理材料的能力。它可以综合处理表格、PDF、图表和音视频，辅助研究分析、整理报告，在覆盖企业知识工作的 Vals Index 中排名第二。科研方面，Google 公布的数学和科学测试也显示出竞争力。



官方还展示了几项3D开发案例：根据历史照片重建图灵的书房，以及制作包含雪痕、雪崩等效果的滑雪模拟器。



成本是另一项重点。Google 称，默认 high 档下，Neon 在相关评测中的单任务成本比 Carbon 低32%。Neon 更明确的定位，是让复杂工作变得更快、更经济。



模型变强了，为什么Antigravity还被吐槽？


不过，与 Gemini 4 各个模型亮眼的跑分形成反差的，是 Google 自家 AI 编程工具 Antigravity 的用户口碑。



Antigravity 是 Google 推出的一款 AI 编程工具，可以对标Cursor、Claude Code、OpenAI Codex或者GitHub Copilot。


问题是，模型能力越来越强，实际使用体验却没有同步改善。


在社媒上，许多人吐槽Gemini 4拉完了，最大的三个问题是：运行不稳定、长任务容易出错，以及使用额度不可预测。


首先是稳定性。


11月以来，多名开发者反馈，Antigravity 经常出现响应缓慢、任务卡死、模型不可用等问题。一名用户表示，升级软件后，即便只是修改几行代码，AI 也会反复搜索、循环执行，原本几秒钟的任务甚至拖到一两个小时，最后只能强制终止。


比速度更麻烦的是，AI 可能在完成任务的过程中忘记自己要做什么。


11月17日，一名 Google AI Ultra 用户公布了一组复现测试：当对话超过约12.8万 Token 时，Antigravity 中的 Gemini 4 模型可能在没有提示的情况下丢失早期上下文。


另一个问题是额度。Google 采用五小时额度与每周额度并行的限制机制，复杂任务消耗更多资源，却不容易提前估算。一名 Ultra 订阅用户甚至报告，已经完成工作的16个子 Agent 仍长时间显示运行，持续消耗额度。


当然，Antigravity也不是完全一无是处。今年9月，Kommunicate团队让 Claude Code、Codex 和 Antigravity 完成同一项邮件处理系统开发任务。结果，Antigravity 做出了功能最丰富的原型，不仅支持动态路由和失败重试，还额外设计了管理看板。但它也没有完成真正的 Gmail 邮件接入，部分功能超出了原始需求，启动时还发生过两次崩溃。


另一项测试则展现了它不同的优势。10月，TLE Labs 用168个代码变更请求测试三款工具的代码审查能力。面对本身没有问题的代码，Antigravity 的误报比例仅为5.2%，低于 Claude Code 的20.7%和 Codex 的47.8%。


但代价是，它也更容易漏掉真正的错误。在按严重程度加权的缺陷检出率上，Antigravity 为70.7%，而 Claude Code 和 Codex 分别达到89.2%和91.6%。


谷歌就是这样，总是差点意思。谷歌这盏能力领先的霓虹灯能亮多久，还是得回归整体工程。
