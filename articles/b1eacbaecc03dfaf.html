用户发现部分Claude会话被路由到更新的模型，Fable 5.5仍在测试。更值得注意的是回答之后那条看不见的安全复盘指令，它不是实时拦截，却把生成与审查塞进同一条链路，代价与误判风险都要算。

Fable 5.5测试曝光，Claude每次回答后，还会执行一条你看不到的指令

Gemini 4 Carbon 刚进入讨论，Anthropic 新模型 Fable 5.5 又被曝出正在测试。用户反馈显示，部分 Opus 5.5 会话可能被路由到了更新的模型：它更能理解隐含目标，也更擅长复杂 SVG 和 Three.js 交互。

更值得关注的是自评估安全机制。Claude 完成回答后，会在用户看不到的上下文中追加安全复盘指令，判断整段对话是否可能涉及滥用，并把结果用于离线筛查。这不是实时拦截器，也不代表所有流量都会启用，但它把“模型生成”和“模型审查”放进了同一条工程链路。

Fable 5.5仍是测试传闻，不是正式发布

现有信息来自用户反馈和外部爆料，Anthropic 尚未正式公布 Fable 5.5 的名称、发布时间、完整能力或公开评测。Opus 5.5 会话被路由到更新模型，只能说明服务端可能存在实验分流，不能证明所有请求都进入同一个新模型。

测试结果还会受到提示词、会话历史、工具权限、系统提示和路由策略影响。开发者不要用单次回答给模型贴上“已经发布”或“全面领先”的标签，更适合把它当作早期信号观察。

复杂任务能力：从修一个Bug到追查一类问题

一个典型场景是：用户只要求修复某个 Bug，模型却继续追查导致 Bug 的底层模式，发现其他模块里存在类似问题，再询问是否要扩大修复范围。

这种主动发现能减少提示词往返，但不能自动扩大授权。Agent 应当把输出拆成当前错误、最小修复、关联位置、证据、影响范围和后续建议，批量修改前等待确认。

这类模型也被用于生成复杂 SVG、游戏掌机界面和交互动画。视觉产物可以作为能力信号，但工程验收还要看源码结构、资源体积、控制台错误、移动端布局和可维护性。



Three.js实测：视觉结果只是第一层验收

网友将 Opus 5.5、Gemini 4 Argon 和疑似新模型放在一起生成 Three.js 奔跑斑马。主观反馈认为，Fable 5.5 的画面更像真实奔跑，其他模型的动作显得吃力。

但“看起来更真实”不能直接等同于“更适合生产”。固定相机、固定动作和可复现脚本可以减少主观截图偏差；帧率、输入响应、浏览器兼容性和控制台错误，才是交互代码进入项目后的基本验收项。

知识范围差异，不能简单归因于模型更聪明

网络讨论中有一种测试：询问 Andrej Karpathy 在 2026 年 5 月的去向，并要求模型不要搜索。通过 API 调用的 Opus 5.5 只能回答到更早时间，而被疑似新模型路由的 Claude 会话给出了更新信息；GPT-6 和 GPT-6.1 Terra 也没有准确回答这个问题。


这个结果可能来自训练数据、系统上下文、路由配置或服务端检索能力差异，不能单独证明模型拥有更强的实时知识。生产系统仍应对关键事实保留检索、时间戳和来源字段。

自评估：回答结束后再做一轮安全复盘

Anthropic 公开的自评估思路，是让 Fable 5 及后续模型在正常回答之后执行一条用户不可见的指令，反思整段对话是否涉及潜在滥用，并输出固定格式的风险判断。它主要用于离线筛查，不直接替代回答前的实时安全分类器。

工作流可以抽象成：

用户提问

-> Claude 生成正常回答

-> 追加隐藏安全评估指令

-> 输出 flagged 与风险说明

-> 聚合风险信号

-> 高精度分类器或人工复核

自评估利用 KV Cache 复用已有对话上下文，公开描述中的额外算力开销不到 2%。回答完成后再快速启动第二轮审视，不需要完全重新处理整段上下文。



这种方法解决的是离线筛查成本，不是所有安全问题。实时阻断、权限控制、工具网关和人工升级仍要独立存在；自评估模型也可能误判，不能成为唯一的安全裁判。

“AI自己审自己”带来的隐私边界

每次回答都被再次评价，用户自然会关心：哪些讨论会被标记，复盘结果谁能看到，数据保留多久，是否会进入后续训练。

如果系统只把自评估当作内部风控，体验会更稳定，但透明度会下降。可持续的产品设计至少要说明哪些流量启用自评估、零数据保留流量是否排除、风险结果是临时信号还是账号标签，以及用户如何申诉误判。

安全监控不是增加一个隐藏提示词就结束了，而是新增了一条数据处理链。它需要和隐私政策、数据保留、访问控制、审计权限和误判申诉一起设计。

研究型安全机制如何落地到Agent系统

对开发者而言，自评估最值得借鉴的是“生成结果后再进行独立审查”的旁路架构：

  1. 执行模型完成任务并生成结果。
  2. 安全评估器读取规范化事件和工具调用记录。
  3. 发现风险后升级到更强分类器或人工。
  4. 评估结果写入独立审计日志。
  5. 任务状态和权限根据策略决定是否继续。

执行模型不能修改安全评估开关，也不能决定哪些日志被送入评估。对于代码 Agent，安全旁路至少要看到文件修改、命令、网络访问、凭据使用和外部副作用，而不是只看最终回答。

国内团队若需要把 Claude Code 等工具接入兼容 API，可通过 Code80(https://code.ai80.vip/home) 配置 endpoint；安全审计、数据保留、权限和申诉流程仍应由项目侧控制。

常见问题

Fable 5.5已经正式发布了吗？

没有。目前信息来自用户反馈、外部爆料和测试行为，Anthropic 尚未正式公布模型名称、发布时间和完整评测。

自评估会直接决定模型能否回答吗？

按公开描述，它主要用于回答完成后的离线筛查，不直接替代实时安全分类器。具体处置取决于平台整体安全系统。

为什么要用同一个模型做安全复盘？

复用 KV Cache 可以降低额外算力和延迟，但同一模型也可能继承原回答中的偏差。高风险场景仍应使用独立分类器、工具网关或人工复核。

如何评估新模型是否适合开发？

使用固定仓库、固定任务和固定工具权限，比较首轮成功率、测试通过率、Token、工具调用、耗时、返工和回滚，而不是只看创意 Demo。
