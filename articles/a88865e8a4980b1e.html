Vercel Labs 已将 fx 作为开源项目发布，这是一个用 Zig 语言编写的实验性编码代理和命令行工具，以脚本化或嵌入式的方式使用，而非作为全屏终端应用程序运行。

fx 于 2026 年 8 月发布，以一个 6.3 MiB 的原生二进制文件形式提供，据称其内存基线为个位数 MB，冷启动时间为 10 微秒——这些数据由 Vercel 提供，而非经过独立验证的基准测试结果。fx 不会通过持久化界面接管终端，而是将对话内容写入普通的滚动历史记录中，并通过命令行界面（CLI）和库两种方式提供相同的引擎。

该项目主要面向构建代理基础设施的开发者，而非那些只是想再开一个聊天窗口的用户。它提供了结构化输出以支持自动化，因此脚本或持续集成任务可以调用命令并解析响应：

fx ask --json "summarise the failing tests"

开发者可以使用 fx acp 通过 Agent Client Protocol 协议进行连接，而 libfx 则将引擎暴露给 JavaScript，其中包括一个 WebAssembly 构建。

此外，Hacker News 上早期反馈也对“模型无关”这一说法提出了质疑。一些首次试用报告称，该系统似乎是通过 Vercel AI Gateway 进行推理的。评论者们则质疑， fx 似乎与现有的代理没什么不同，并且指出，OpenCode 提供了更成熟的终端体验。

有用户指出，GLM 5.2 是免费的：

刚试用了一下，虽然我觉得它还不够完善，速度也不算快，但确实很酷。

即使使用免费的 Vercel 账户，GLM 5.2 也是完全免费的。

这在商业上也很有意义——fx 是吸引更多用户使用 Vercel AI 的入口。

此后，服务提供商的选择范围会进一步扩大：0.0.11 版本为本地服务器和替代网关添加了兼容 OpenAI 的可命名连接选项，README 文件现在已经列出了 Vercel AI Gateway、ChatGPT 和 Grok 订阅服务，以及 Ollama 和 OpenRouter 等端点。Vercel 还将 fx 纳入了其 AI SDK 治理框架层，与 Claude Code、Cline、Codex、Cursor、OpenCode 和 Pi 并列，呈现为共享接口下的一个选项。

GitHub 上的一则问题报告指出，其名称与久负盛名的终端 JSON 查看器 fx 存在命名冲突——后者已经在 Homebrew 软件包管理器中正式收录——一位贡献者确认，目前正在审查软件包与命令的共存问题。

Vercel 明确指出，fx 尚处于实验阶段。10 月 4 日发布的 0.0.13 版本在支持的 OpenAI 模型上新增了“超快模式”（Ultrafast mode），可以加快启动和 shell 调用速度，但同时也警告称，新创建的 libfx 检查点无法由旧版本恢复。

CLI 用户可以通过 fx upgrade 命令进行版本升级，并且应该先阅读变更日志；而嵌入式用户则应该参考 libfx 迁移指南，其中说明了早期 createFxAgent() 调用在当前文档中对应 createFxEngine()。

其代码库中记录了 CLI、技能、MCP、权限和 SDK 的相关文档，其浏览器演示则展示了无需安装即可体验的终端风格的操作界面。

fx 是 Vercel Labs 推出的一项开源项目，Vercel Labs 是 Vercel 旗下的实验团队，而 Vercel 正是 Next.js 框架及其配套 Web 应用构建部署平台的开发方。fx 采用 Zig 语言编写，以单个原生二进制文件的形式发布，设计上既可以通过命令行运行，也可以用于自动化脚本，还可以通过其 libfx 库和 WebAssembly 构建直接嵌入到其他应用程序中。该项目目前仍处于 1.0 版本之前的快速迭代阶段，体现了将编码代理视为可组合基础设施而非独立工具这一广泛的趋势。
