两台没有公网 IP 的电脑，两个不同厂商的 Agent，过去通常只能靠人复制上下文、粘贴消息，再把结果传回去。AgentHop 提供了另一种方式：用一个配对码建立加密通道，让两个 Agent 直接对话。

它可以接入 Claude Code、Codex、Cursor、Gemini CLI 和 grok，把跨机器协作变成 MCP 工具。Agent 负责交换版本、复核结果、传递文件和同步状态，人不再需要充当传话筒。

三步建立连接

1. 安装

AgentHop 提供 macOS、Linux 和 Windows 单文件版本，不需要先搭建 Node.js 环境：

chmod +x agenthop-macos-arm64

./agenthop-macos-arm64 install –skill-dir

Windows 可在 PowerShell 中执行：

.\agenthop-windows-x64.exe install –skill-dir

2. 接入 MCP

安装后，将 AgentHop 注册为 MCP 服务：

claude mcp add –scope user agenthop — ~/.local/bin/agenthop mcp

grok mcp add –scope user agenthop ~/.local/bin/agenthop — mcp

也可以让工具自动写入 Claude 配置：

agenthop install –mcp claude

3. 创建或加入房间

创建方发送任务描述：

agenthop “我们来核对一下 v0.3.2 的发布情况”

程序会返回配对码，另一台机器加入：

agenthop 0064-fresh-genre-bunt-k7f3q2mbxz4a6tu5wnhjy2pc3d

连接建立后，两个 Agent 可以直接交流。配对码应通过安全渠道传递，任务结束后及时清理房间和联系人。

MCP 工具与协作流程

AgentHop 提供创建、加入、发送、等待、传文件和查看状态等工具：

工具作用
create创建房间并返回配对码
join加入房间并获取对方背景
say发送消息
working回报处理状态
wait等待对方回复
send_file加密传递文件
status查看连接状态
bye结束会话

一次典型协作可以拆成：

  1. 本地 Agent 提出需要复核的问题；
  2. 远端 Agent 查询自己的代码或环境；
  3. 对方返回版本、测试或文件结果；
  4. 本地 Agent 根据结果继续执行；
  5. 双方结束会话并保留审计记录。

联系人机制可以保存首次对话中的长期公钥。后续使用名字邀请，不必每次重新传配对码；但对方必须在线，邀请不会排队唤醒离线进程。

配对码由房间地址和随机密钥组成。前半部分用于中继路由，密钥不会发送给中继服务器，因此中继只能看到通信时间、数量和大小，不能读取消息与文件内容。

这并不等于绝对安全。中继仍可能丢弃或延迟消息；系统也没有前向保密，长期密钥泄露后，历史通信的保护能力可能受影响。联系人采用首次使用信任，重要协作应额外核对公钥指纹。

适合什么任务

AgentHop 适合明确的跨 Agent 协作：

  • 一个 Agent 负责调查，另一个负责复核；
  • 本地 Agent 读取代码，远端 Agent 提供测试环境；
  • 两个团队分别运行 Agent，共同核对发布版本；
  • 一个 Agent 负责规划，另一个负责执行并回报状态；
  • 在不同机器之间传递加密文件和结构化结果。

它不是远程控制工具。连接建立后，对方不会自动获得你的终端、文件或网络权限；具体操作仍由各自机器上的 Agent、操作系统和工具授权决定。

国内开发者需要把 Claude Code 等兼容 Agent 接入跨机器协作时，可以通过 Code80 配置 endpoint：

$env:ANTHROPIC_BASE_URL = “https://code.ai80.vip”

$env:ANTHROPIC_AUTH_TOKEN = “<你的 API Key>”

常见问题

AgentHop 需要公网 IP 或端口转发吗？

不需要。两端通过中继建立加密通信，适合家庭和办公网络。

中继服务器能看到对话内容吗？

按设计只能转发密文，但仍能看到时间、大小和数量，也可以丢弃或延迟消息。

配对码可以长期复用吗？

配对码包含一次性随机密钥，不应公开传播。长期联系人可以保存公钥并使用邀请机制，但首次建立信任时应核对身份。

连接后能直接操作对方电脑吗？

不能。AgentHop 传递消息和文件，命令、文件和网络权限仍由各自机器控制。

离线 Agent 能收到邀请吗？

不能。邀请只能到达正在运行 AgentHop 的 Agent，不会排队唤醒离线进程。
