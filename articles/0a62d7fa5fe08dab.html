Anthropic 把 Max 20x 改名 Ultra，并向已验证账户放开 5 小时窗口限制，但每周总额度没变。限流从短窗口变成周预算调度，长任务不再被硬中断，却更容易一口气烧掉整周预算，任务编排与 Token 观测都得跟着改。

对使用 Claude Code 做长时间开发任务的人来说，最难受的往往不是模型不够强，而是任务做到一半突然撞上 5 小时使用窗口。代码还没有跑完，测试还在排队，Agent 却只能暂停，等窗口恢复后再继续。

Anthropic 最近调整了 Claude 的个人订阅命名，并开始为已验证的 Ultra 账户逐步取消 5 小时使用限制。Max 5x 更名为 Max，Max 20x 更名为 Ultra，价格和原有权益不变；Ultra 用户不再受 5 小时窗口限制后，可以持续使用 Claude，直到触及每周额度。

这不是把额度变成无限量，也不是单纯提高模型上限。真正的变化是额度从“短窗口限流”转向“周预算调度”。对于开发者来说，Agent 的任务编排、并发控制和 Token 观测都需要跟着改变。

Claude套餐发生了什么变化

Claude 的个人订阅现在形成 Free、Pro、Max 和 Ultra 四个档位。原来的 Max 5x 改名为 Max，每月 100 美元；Max 20x 改名为 Ultra，每月 200 美元。现有订阅用户不需要操作，名称会自动切换，价格与权益保持不变。

需要注意的是，名称变化并不等于额度倍数发生变化。名称中的“5x”和“20x”容易让用户误以为短窗口和每周额度都相对 Pro 放大同样倍数，而实际规则并不是这样。Anthropic 去掉倍数标识，主要是为了减少新用户对套餐额度的误读。

已验证的 Ultra 账户开始逐步解除 5 小时使用限制，大多数已有订阅用户会率先受益。新注册的 Ultra 账户暂时仍受 5 小时限制约束，完成账户验证后，平台会通过邮件通知解除。

取消5小时限制，不等于无限使用

Ultra 仍然保留每周额度。通过验证后，用户可以连续使用 Claude，直到触及本周上限；本次调整没有增加用户一周内可以消耗的总量。

可以把变化理解成两种不同的限流方式：

规则调整前调整后
5 小时窗口可能先触发，任务被迫暂停已验证 Ultra 逐步取消
每周额度保留继续保留
每周总用量不变不变
任务连续性容易被短窗口打断可以持续运行到周额度耗尽

对于原本就会提前耗尽每周额度的重度用户，实际可用总量并没有增加；变化主要体现在额度的使用方式。过去，用户可能还有剩余周额度，却因为 5 小时窗口触顶而暂停任务。限制取消后，长任务可以继续运行，但更容易在短时间内消耗掉一大块周预算。

每月 100 美元的 Max 用户只是名称调整，5 小时和每周使用上限仍维持在 Pro 的 5 倍。Ultra 则相当于从“短窗口加周额度”切换为“直接受周额度约束”。

对Claude Code长任务意味着什么

Claude Code 的任务通常不是一次回答就结束。一个真实的软件工程任务可能包含读取仓库、分析依赖、修改多个文件、运行测试、修复失败、更新文档和生成变更说明。每一步都会产生上下文、工具调用和输出 Token。

过去的 5 小时窗口像一个硬断路器：即使任务本身还没有达到周额度，Agent 也可能被迫停止。取消窗口限制后，任务连续性提高了，但预算消耗的速度也更需要被看见。

开发者至少应该为长任务记录以下指标：

  1. 当前任务已经消耗的 Token 和预计剩余额度。
  2. 主 Agent、子 Agent 和工具调用分别占用了多少预算。
  3. 任务已经运行多久，最近一次有效进展是什么。
  4. 失败重试、上下文压缩和重复读取分别发生了几次。
  5. 任务是否接近周额度阈值，是否需要切换到低成本模型。

没有这些数据，用户只会看到“Claude 还能不能用”，却不知道额度究竟花在了哪里。对于团队来说，订阅上限也应该被当成一种共享资源，不能让一个无限重试的后台任务耗尽所有人的可用空间。

以前的命名为什么容易引起误会

2025 年 4 月，Anthropic 推出最高档订阅时，套餐只有一个 5 小时用量窗口，窗口额度是 Pro 的 20 倍，所以命名为 Max 20x。后来平台又增加了每周使用上限：5 小时窗口仍然保持 Pro 的 20 倍，但每周额度只设置为 Pro 的 10 倍。

于是，“20x”同时出现在产品名称和短窗口规则里，却没有准确反映每周额度。新用户很容易把它理解成所有时间维度都是 Pro 的 20 倍，实际使用时自然会产生落差。

这次改名的价值不在营销，而在于把产品名和真实计费规则拆开。对复杂 AI 产品来说，名称越简单，越应该用独立的用量面板补足细节：当前窗口额度、周额度、缓存命中、工具调用和预计恢复时间都应该直接展示。

周额度模式下，Agent应该怎样调度

取消短窗口限制后，长任务可以不间断执行，但并不适合把所有工作都交给最高档模型。更稳妥的方式是把任务分层：

  • 代码仓库索引、日志归类和简单文档修改，使用低成本模型或预处理流程。
  • 跨文件重构、复杂调试和测试修复，交给主 Agent 连续执行。
  • 数据库迁移、生产配置和外部发布，必须停在人工审批点。
  • 长时间无人关注的任务，设置最大执行时间、最大工具轮数和预算阈值。

可以把一个长任务设计成检查点驱动的流程：

读取任务目标

-> 建立仓库状态快照

-> 分析并生成执行计划

-> 分阶段修改和测试

-> 保存 diff、日志和测试结果

-> 预算接近阈值时暂停

-> 人工确认后继续或回滚

这种方式可以避免“窗口限制取消了，Agent 就一直跑下去”的错觉。任务连续性提高后，回滚和暂停点反而更重要。

Ultra用户还需要关注哪些边界

首先是验证状态。已验证账户和新注册账户的规则不同，不能把“Ultra 已取消 5 小时限制”理解成所有账户立即生效。实际可用状态仍要以账户页面和 Anthropic 的通知为准。

其次是周额度。取消 5 小时限制只是改变了消费节奏，不能突破每周总量。对于需要持续运行代码 Agent 的用户，应该在任务开始时估算剩余预算，把长任务拆成可以独立验收的阶段。

最后是团队共享。个人订阅用于高频开发时，后台任务、多个项目和并发会话很容易互相争抢额度。项目侧应该保存自己的调用账本，至少区分项目、任务、模型、工具和用户，避免出现“套餐还有额度，但关键任务无法使用”的情况。

Anthropic 还表示，后续会继续推进产品更新。对开发者而言，真正值得观察的不是套餐名称，而是平台是否会提供更清晰的额度可视化、任务级预算、团队共享控制和 API 级别的长任务管理。

国内开发者如果需要将 Claude Code 等工具接入兼容 API，可通过 Code80(https://code.ai80.vip/home) 配置 endpoint；订阅额度、模型权限、密钥隔离和生产审计仍应由项目侧管理。

常见问题

Ultra取消5小时限制后可以无限使用吗？

不能。已验证 Ultra 账户可以持续使用 Claude，直到触及每周额度；每周总量没有因为取消 5 小时窗口而增加。

新注册的Ultra账户什么时候解除限制？

目前新注册账户暂时仍受 5 小时限制约束，完成账户验证后，Anthropic 会通过邮件通知解除，具体时间以账户状态为准。

Max更名后额度变多了吗？

没有。Max 5x 更名为 Max，价格和权益不变，5 小时和每周使用上限仍维持在 Pro 的 5 倍。

为什么要取消20x标识？

因为“20x”容易让用户误以为 5 小时额度和每周额度都达到 Pro 的 20 倍。改为 Ultra 后，套餐名称不再直接暗示一个并不完整的倍数关系。

Claude Code长任务应该怎样避免耗尽额度？

设置任务级预算、最大工具轮数和执行时间，保存中间检查点，并把简单任务、复杂重构和生产变更分配给不同模型和权限等级。

国内开发者如何接入兼容 API？

可以通过 Code80 了解接入方式，同时自行管理密钥、权限、数据留存、用量预算和审计日志。
