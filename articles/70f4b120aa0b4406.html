传说，光明之神巴德尔梦见自己将死，于是，巴德尔的母亲弗丽嘉遍走世间，令万物立下了绝不伤害他的誓言。众神也因此放下心来，甚至还发明了一种新的消遣：轮番向巴德尔投掷武器和石块，看着他毫发无损，来确定他们已经战胜了预言。直到一小枝被遗漏的槲寄生投向巴德尔。光明之神轰然倒下，诸神的黄昏由此拉开序章。

这是北欧神话中巴德尔之死的故事。危险早已被预见，人们也采取了行动，却仍然自欺欺人，把一次次看似成功的演示，当成了问题已经解决的证明。

2026 年上半年的企业级 Agent 市场，也曾有过这样的笃定。

每一场发布会上，AI 写方案、做表格、敲代码、生成海报的单任务能力都会轮番刷新上限。台上演示环节的百发百中，带动台下掌声雷动，所有人都觉得——企业级 AI 已经成熟了。

但年中效率复盘，所有人都尴尬地发现：个人用 Agent 提效能翻三到十倍，落到整个团队、整个企业里，整体效率提升往往不到两倍。一个人把报告写快十倍，并不能让另外三个部门提前给出确认。设计师更快做出了十套方案，运营可能还在等商家确认价格，仓库也还没有更新库存。单个员工的产出增加伴随的，是整个项目仍然要按照原来的方式往前推进。

11 月 9 日，千问办公 2.0 正式发布，直击这些痛点。

作为业内首个面向团队协作的「Team Agent」，千问办公 2.0 版本，把多人协作、文档共创和自动任务整合到同一个 Agent 产品中：团队可以关联原有工作群和资料，围绕同一个 Agent 持续讨论、分工和执行。Agent 可以实时理解项目信息，并和群成员协同工作，像项目经理一样推进项目和执行待办。

而伴随千问办公 2.0 打通生产级上下文，Agent 的 2.0 时代自此拉开序幕。

01

从单机到协作，

Agent2.0 时代来了

如何弥合个体效率提升与组织效率提升之间的巨大鸿沟，是过去一年多企业级 Agent 市场最大的机遇所在。

围绕这个目标，主流探索大致分为两种：给 Agent 增加协作能力，以及给现有办公软件增加 Agent 能力。

多数 Agent 玩家的第一选择是第一种，给 Agent 加一个群聊。把同事拉进同一个 Agent 的项目组，大家一起讨论，AI 自然就有了团队上下文。

这个逻辑看上去顺理成章，但支持多人聊天，只是企业协作的起点。

工作群里为什么需要话题、已读、在线文档，甚至表情包？因为员工每天要在这里确认事情、表达态度、区分轻重缓急。一个被使用多年的工作群，还连接着客户、供应商和合作伙伴，积累着文件、会议与业务记录。

把几位同事邀请进新产品很容易，但让 Agent 获得完整的上下文却需要企业把完整工作流迁移过来。甚至客户沟通、部门讨论、文档修改，最好都发生在这个新产品里。

你可以把同事拉进自己的 Agent，却很难要求客户先安装一个新的 AI 产品，才能向他发送优惠券。

对于企业来说，既有 IM 也远不只是聊天工具。人员关系、权限、审批和业务习惯，都已经形成。企业愿意为新能力付费，并不意味着它可以为新产品重新组织一遍所有人的工作。

也是因此，另一条路径选择反过来，给现有的 IM 工具加 Agent。这是更务实的选择，也确实走通了一多半。

员工不用换地方，就在日常聊天的群里就能@机器人问问题、总结会议纪要、了解项目背景。

可问题在于，IM 终究是沟通场，不是生产场。群里的 Agent 最多能帮你整理聊天记录、提炼会议要点，真要写代码、做设计、改长文档、做复杂数据分析，还是得跳转到专门的生产工具里，上下文到这里也就断了。

讨论在群里，产出在别处，只要还需要员工下载文件、切换软件、重新介绍背景，协作成本就没有消失。

既然两条路都只走通了一半，那么为什么不将它们合二为一呢？

千问办公 2.0 最先把这两种探索结合了起来。

一方面，它关联原有钉钉群和项目资料，让 Agent 了解业务正在发生什么；另一方面，它提供完整的任务执行和内容生产能力，让团队可以围绕同一个 Agent 继续做文档、处理表格、修改方案。

在企业版协作群里，不同岗位可以补充各自掌握的信息，Agent 小 Q 会据此整理进度、共识和问题，再按照团队确认的分工创建待办。有人接手项目，也能先了解当前安排，再继续自己的工作。

销售说过的话，可以成为方案同事产出的工作依据；方案发生的变化，也可以及时反映到交付安排中。团队不必等某个人收集好所有信息，再统一向 AI 下达指令。

Team Agent 也由此与个人 Agent 拉开了区别。

02

实测：AI 如何深度参与真实工作流

千问办公 2.0 发布后，我们第一时间进行了实测。

第一个场景选择了上下文足够复杂、需要做大量搬运工作的月底发票整理场景。

通常来说，报销时，员工会把电子发票发给财务，由财务整理、核对、分类，最后形成报销材料。清晰的流程背后，实际做起来却有许多琐碎的问题：同一张电子发票可能无意中被下载了两次、发送了两次。发票需要被分门别类管理，但不同项目、不同子公司抬头的费用，往往混在相同的上下文里。

每到月底，经常会出现几百张、上千张发票在同一时间被集中提交，完成审核、确认、整理这一套流程，专业财务也需要至少 1~2 天的时间。

于是，我自告奋勇给财务推荐了千问办公 2.0。在千问办公中，直接关联发票报销相关钉钉群，就完成了初步搭建。

接着，我只要一句话描述需求，并添加同事为协作者，千问办公就能自动解决剩下的所有问题。

过去需要一两天，把聊天记录里的文件逐一整理到文件夹，再上传给 AI 的流程，现在 Agent 可以直接自己从群聊中找到需要的内容，然后做汇总分析。

类似的工作在企业中还有很多。通常来说，这类任务本身并不复杂，但材料往往分散在不同人、不同项目中，上下文整合就需要花费大量的时间精力。

与之相对的，还有另一种情况——审批。业务部门可能一天向法务发来 20 款合同，虽然法务只需要回复通过或者驳回，但判断的成本，可能一个合同就要花费半天的时间。

脑暴讨论也是如此。我们团队都有定期追踪行业论文的习惯，不同岗位的同事平时分别关注不同领域，大家会把看到的优质论文发在群里，再由专人汇总整理。这原本是一种很高效的办法，每个人替其他人筛选过一轮，整个团队就能快速掌握各个领域里最有价值的信息。

但随着人数和论文数量增加，对负责整合的同学来说，挨个通读、提炼要点就成了沉重的负担。

最终，我们选择把千问办公的协作空间关联到论文讨论日常群聊。每天新增了哪些论文、每篇论文的核心结论是什么、有哪些值得重点关注的创新点，Agent 全都可以自动梳理清楚。当然，总结群聊内容，产出 PPT，然后分配任务也不在话下。

阅读之后，还有讨论和修改。一些同事会用 PPT 来总结这一周的推荐论文。如果我觉得有问题，或者产生了新的想法，也可以在千问办公里直接与 AI 共同修改这个文档。过去，给 AI 改稿，需要先准确描述位置，再把结果复制回文档。多改几轮，还要核对版本。现在，借助人机共创模式，对话和文档可以被放在同一个窗口，选中需要调整的内容，提出要求，再检查原文中的修改。讨论和编辑围绕同一份文档进行，同事也能沿着这份成果继续工作。

此外，考虑到论文整理定期发生，我又把它设成了自动任务，在每周一和每周三定时执行。一次次重复交代的工作，逐渐变成了固定安排。

 

对我们这种小团队来说，千问办公 2.0 已经解决了大量上下文协作的时间。对那些组织更庞大、上下文更多的企业来说，深度协作带来的效果提升还会变得更加明显。银泰百货的直播卡券业务，就是最典型的样本。

在银泰，直播卡券业务覆盖全国 62 家品牌门店，联动 200 多名门店、商家与运营人员，年 GMV 超过 2 亿元。一张团购券从提报到最终上架，要经过档期确认、资料核对、内容制作、审核发布多个环节，仅需要核对的信息就有名称、价格、有效期、适用门店、素材等近 50 项。

过去，这些工作分散在几十个门店群里推进，没有任何一个群能看到完整的进度。运营人员要逐群翻聊天记录，把信息手动汇总到表格里，再通知下一环节的负责人跟进。大促期间一批卡券集中上线，整个团队要连轴转好几天，大部分精力都耗在了「找信息」和「同步进度」上。

内测千问办公 2.0 之后，事情开始变得不一样。

团队在千问办公里建起一个协作空间，把 60 多个门店钉钉群和卡券 AI 表格全部关联进去。门店的沟通方式没有任何变化，该在群里说什么还说什么，但所有的进度变化都会被 Agent 同步捕捉，自动更新到中央表格里。

负责人想知道一批卡券的准备情况，不用再逐群追问，直接在协作空间里提问，就能得到最新的整体进度。

此外，团队还设置了定时检查任务，Agent 会按固定时间梳理每张卡券的状态，列出已经满足上架条件的清单，再把资料不全、等待审批的事项整理成待办，推送给对应的负责人。

过去是人需要追着信息跑，现在信息和任务会主动找到人，生产协作的模式，开始随着企业级 Agent 的落地，逐渐发生变化。

03

为什么是千问办公？

一个必须承认的事实是，千问办公能够把团队协作和专业 Agent 能力整合起来，原因藏在阿里的业务基因里。

钉钉连接着中国最大规模的企业客户，服务超 2000 万企业组织、近 8 亿用户。千问办公盘活了钉钉沉淀了十几年的企业上下文—— 消息、文档、审批、知识库，这些分散在业务流程里的海量数据，终于能完整、顺畅地喂给 Agent。

不止是钉钉，阿里云、电商平台也都是 2B 的服务。

对很多行业来说，生产创造是工作的主体，上下文搬运只是附加成本，忍一忍也能过去；但在电商与零售行业，运营、营销、客服、库存管理这类岗位，最终的产出可能只是一张报表、一个活动方案、一句客户回复，而九成以上的工作时间，都花在了收集信息、对齐信息、同步信息上。

上下文的摩擦力，是这类岗位每天都要面对的核心痛点。阿里本身就是全球最大的电商经济体之一，从淘宝天猫到银泰、菜鸟，内部有数百万从业者天天在这种痛点里打转。这种浸泡在真实业务里的体感，是纯 AI 实验室出身的团队，很难天然具备的。

最后，也是最容易被忽略的一点，是阿里滚雪球效应带来的更多行业 know how。

千问办公上线首月用户就突破 3000 万，其中企业用户占比过半，这意味着它从很早开始，就已经被海量真实企业用户推着往前走。

9 月云栖大会上发布的「企业上下文」能力，本质就是 2.0 版本的技术前置——基于对企业数据的结构化处理，企业上下文能让 Agent 能真正读懂组织的业务逻辑。从企业上下文到 Team Agent，这条路不是凭空想出来的，是阿里内部几万员工先用起来，是银泰、古茗这些生态企业一轮轮内测磨出来的。

当然，现在的 Team Agent 还只是起点。按照千问办公的规划，未来自动任务还会接入更多企业内部 OA 与第三方 SaaS 应用，协作能力也会覆盖飞书、企微在内更多 IM 平台，让企业选择 Agent 时，不必因此重新选择一套 IM。

04

尾声

1913 年秋天，美国底特律高地公园工厂，亨利·福特创建了世界上第一条汽车生产流水线，由此，汽车制造从工人围绕固定装配位置取用零件、完成工序的工匠式活计，升级为按照生产顺序安排工位的流水线式生产。自此，磁电机组装从 20 分钟降到了 5 分钟，整车下线从 12 个半小时压缩到 90 分钟。

工人没有获得八倍的手速的情况下，工作被重新组织、减少不必要的搬运，就带来了八倍的生产力跃升。

这也是今天企业级 Agent 正在完成的转变。从 AI 加速个体的生产流程，到 AI 重构组织的协作模式，个人能力的增长，终于有机会转化为组织生产力的跃升。

这一次，Agent 的流水线时刻，真的来了。
