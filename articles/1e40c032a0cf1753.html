我的 DJI Pocket 4 通过 USB 接到 Mac，在 StreamYard 里已经选择了 1080p，Chrome 的摄像头轨道也报告 1920×1080、30 帧，但相机机身仍然显示 4K30。结果是：macOS 的人像和背景替换无法使用，只剩下屏幕氛围灯。

最后解决这次问题的，并不是再调一次 StreamYard 的分辨率，而是在 Chrome 启动时加入一个参数：。完全退出并重新启动 Chrome 后，Pocket 4 机身变成了 1080p30，macOS 抠像也恢复可用。--disable-features=ConfigureCaptureBeforeStart

这是一次具体设备和软件组合上的实测记录。它说明这个方法在我的环境里有效，尚不能证明所有 Mac、摄像头或 Chrome 版本都会有相同结果。

为什么网页显示 1080p，机身却仍然是 4K30

排查时最容易被误导的，就是 StreamYard 页面上的“1080p”。网页拿到的视频大小，与 USB 摄像头实际使用的采集格式，不一定是同一件事。浏览器和系统的采集链路可以处理画面尺寸，因此网页显示 1080p，仍不能单独证明相机已经从 4K 切换到了 1080p。

这次我们同时查看了三个位置：StreamYard 的相机设置、Chrome 的视频轨道信息，以及 Pocket 4 的机身显示。前两处都显示 1080p30，机身却显示 4K30，macOS 的效果菜单也没有恢复。这就是为什么单看网页的设置，无法判断问题是否已经解决。

对这台设备查询 macOS 的摄像头格式能力时，1920×1080 格式报告支持人像、摄影室灯光和背景替换；3840×2160 格式报告不支持这些效果，但支持屏幕氛围灯。这与实际看到的菜单差异一致。这个结果针对本次设备和系统组合，不能扩大成“所有 Mac 在 4K 下都无法抠像”。

同一个 StreamYard 网站，换成 Firefox 打开后，Pocket 4 机身会显示 1080p，抠像也能使用。不过此前使用 Firefox 一段时间后可能发生断流，原因还没有查清。因此，我希望继续使用 Chrome，同时让它正确切换相机格式。

加的到底是什么配置

完整参数是：

--disable-features=ConfigureCaptureBeforeStart

是 Chrome 的启动参数，用来关闭指定的内部功能。 对应的是苹果平台摄像头采集的一条初始化路径。--disable-featuresConfigureCaptureBeforeStart

我们核对了这台电脑安装版本对应的 。在这个版本中，该功能默认开启：先设置选定的摄像头格式，再启动采集。关闭它之后，代码执行的顺序变成：先启动采集，再设置选定的摄像头格式。Chromium 摄像头源码

因此，这个参数没有直接写入“1920×1080”，也不是一个“所有摄像头强制 1080p”的开关。StreamYard 仍然需要请求 1080p30；改变的是 Chrome 在 macOS 上落实摄像头格式时的启动顺序。这个改动作用于使用该采集路径的 Chrome 摄像头会话，并不只限定 Pocket 4。

Firefox 的完整实现与 Chrome 的这条备用路径并不完全相同。这个方法应当理解为：针对我们发现的初始化差异，选择一个有源码依据的 Chrome 采集顺序，再用真实设备验证。它不是给 Chrome 安装了 Firefox 的摄像头驱动。
