Tailscale 是一款基于 WireGuard 的组网工具，可以让不同地点的电脑、服务器、NAS 组成一个私有网络。比如你在家中访问办公室的网络资源，在安装了 Tailscale 之后，最终效果就是家与办公室之间就像在一个局域网之内。

Tailscale SSH 出了什么问题？

启用 后，就可以通过 SSH 连接到每一台设备。Tailscale SSH

在 Linux 上，Tailscale SSH 服务器运行在 后台进程中，而这个进程通常拥有 root 权限。tailscaled

研究员发现，在特定 SSH 端口转发条件下，攻击者可能利用高权限的 访问本来不应该由普通用户访问的 Unix Socket，最终实现权限提升。tailscaled

测试设备版本：tailscale v1.104.2，headscale v0.29.5

实验室测试中，每攻陷一台设备耗时不到 1 秒，直到所有允许访问的设备都被攻陷，并且会自动传播。

Tailscale 官方回应

截止目前，尚未有针对这些发现的 CVE 编号、GitHub 安全公告、Tailscale 安全公告或修复版本。

来自 的说法，Tailscale 工程副总裁 Mike Shaver 于 2026 年 10 月 25 日 00:41 UTC 在 上发布了一份声明。threatwirer/Tailscale

要点如下：

  • Tailscale 已收到研究人员的报告，目前正在审查中。
  • 该公司自己的团队以及外部安全专家此前已经展开调查。这项工作“发现了一些我们正在努力解决的问题”。
  • 目前发现的大多数问题都与用户获得连接授权后发生的情况有关，特别是 Unix 权限和 SSH 转发方面的问题。会话“可能能够执行超出已配置本地用户应有权限执行的操作”。
  • Tailscale 表示，这“与未经身份验证的攻击者能够连接到任意机器的情况并不相同”。
  • 目前仍在验证全部影响范围，包括哪些配置会受到影响。
  • “根据我们目前的评估，我们不建议所有人禁用 Tailscale SSH。”
  • Tailscale 将发布一份安全公告，其中包含已确认的发现、受影响的配置和补丁，然后发布一份技术说明。

在 Hacker News 上，一位 Tailscale 的工程师也对报告中的一项说法提出了质疑。Windisch 表示，每个节点都可以看到完整的对等节点列表。他指出，这可能是 headscale 架构的差异：Tailscale 自身的控制平面会对网络映射进行精简，因此彼此之间没有 ACL 路径的节点无法看到对方。

目前，公开代码中已经出现部分修复工作，包括 Serve 权限问题，以及将 SSH 端口转发操作隔离到独立特权进程的改动。

如何关闭 Tailscale SSH？

在需要关闭 Tailscale SSH 的设备上执行：

sudo tailscale set --ssh=false

这条命令只会关闭 Tailscale 内置的 SSH 服务器，不会断开 Tailscale 网络连接，也不会关闭系统自带的 OpenSSH 服务。

如果之后需要重新启用：

sudo tailscale set --ssh=true
