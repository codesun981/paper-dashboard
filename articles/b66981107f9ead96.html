大家好，分享一下我最近在做的一个开源项目： https://github.com/hybroai/hybro 。

随着 Claude Code 、Codex 、OpenClaw 、Ollama 等 Agent 工具越来越多，我发现一个问题：每个 Agent 都有自己的运行环境、工具体系和交互方式。单独使用它们已经很强大，但如果想让不同的 Agent 互相发现、沟通和协作，仍然需要自己写不少 glue code 。

比如：

想让一个 Agent 负责规划，另一个 Agent 负责执行，还有一个 Agent 做 review ； 想把本地运行的 Agent 和远程 Agent 组合起来； 想让不同框架、不同模型、不同运行环境中的 Agent 通过统一的方式协作； 不想被某个特定的 Agent 框架或平台绑定。

这些事情看起来应该很自然，但实际做起来，Agent 之间的协同操作仍然是个问题。

所以我开始做 Hybro：一个基于开放 A2A 协议的 AI Agent 互操作与协作平台。

目前实现了什么？ 多 Agent 协作：将多个 Agent 放进同一个 Room ，让它们围绕一个任务协作。 本地与远程 Agent 互通：统一管理和调用不同环境中的 Agent 。 A2A 支持：发现、检查和注册兼容 A2A 协议的 Agent 。 实时执行过程：通过流式响应查看 Agent 的执行进展，并支持需要人工介入的交互。 不同执行模式：既可以直接调用 Agent ，也可以使用更高层的协调模式处理复杂任务。 本地优先：支持在自己的机器上运行核心服务，使用自己的模型和配置。

项目采用 Next.js 、TypeScript 、FastAPI 、Python 等技术栈，目前仍在持续迭代中。

快速开始

需要 Docker 等运行环境，具体依赖和配置见项目文档。

git clone https://github.com/hybroai/hybro.git cd hybro ./scripts/hybro setup ./scripts/hybro start --build

启动后访问：

http://localhost:3000

文档： https://docs.hybro.ai/

接下来想解决的问题

我更关注的方向不是再造一个封闭的 Agent 平台，而是让现有的 Agent 和 Harness 能够更容易地协作。

例如，Claude Code 和 Codex 能不能像两个独立的工程师一样，在保留各自运行环境和能力的同时，围绕同一个任务交换上下文、交接工作、传递产物，并让整个过程可追踪？

我认为这类互操作基础设施会越来越重要。Hybro 目前主要围绕 A2A 和现有 Agent 生态进行探索，希望逐步把不同 Agent 之间的连接、发现、调用与协作做得更标准化。

当然，离真正通用、可靠的 Agent 协作还有很多问题需要解决，也很欢迎大家一起讨论。
