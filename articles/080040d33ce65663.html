本期的 Java 新闻汇总主要包含如下内容：Atmosphere 4.0 的 GA 版本发布，GraalVM、Azul Payara 与 Quarkus 的小版本发布，WildFly 41 的维护性发布，Jakarta Data 与 Eclipse JNoSQL 的里程碑发布，2026 年 9 月版 Open Liberty 的 beta 发布，以及 GlassFish 8.0.4 的 Docker 镜像发布。

OpenJDK

JEP 542，PEM Encodings of Cryptographic Objects，已经从 JDK 28 的 Proposed to Target 状态提升为 Targeted。该 JEP 在 JDK 25 至 JDK 27 进行了三轮预览后准备将此功能最终定稿。该功能提供了“一个用于将表示加密密钥、证书和证书吊销列表的对象编码为广泛使用的隐私增强邮件（Privacy-Enhanced Mail，PEM）传输格式，并将该格式解码回对象的 API。”该 JEP 将支持在 PEM 文本与PKCS #8与X.509二进制格式之间的转换。变更包括，将 PEM record 类重新归类为常规类，以便提供接受 Base64 编码字节数组内容的构造函数，以及将DEREncodable接口重命名为BinaryEncodable，以更准确描述存储在 PEM 文本中的二进制数据。

JDK 27

Build 35仍然是 JDK 27早期访问构建的当前版本。有关此发行的更多细节请参见发布说明。

JDK 28

JDK 28早期访问构建版本Build 13发布，包含对 Build 12 的更新，修复了若干问题。更多细节参见发行说明。

对于JDK 28和JDK 27，鼓励开发者通过Java Bug Database报告缺陷。

GlassFish

OmniFish团队已为 GlassFish 8.0.4 及 GlassFish Embedded 发布了 Docker 镜像，详情及使用说明见该项目的用户指南。

GraalVM

GraalVM 25.3 版本发布带来若干重要功能，例如，新增的SubstratePriorityInliningPhase类，为 JIT 与 Native Image 模式实现优先内联器（inliner），以提升生成代码的性能，以及增强的安全加固机制，可防止攻击者将程序执行重定向到意外的代码位置。更多细节见发行说明。

Jakarta EE

Jakarta Data 1.1.0 的第四个里程碑发布包含缺陷修复、文档改进、依赖升级及新特性，例如，更新的 TCK 测试，通过@OrderBy注解指示 null 排序的能力，以及使用 Jakarta 注解规范中定义的@Nullable与@Nonnull注解改进空值安全性。更多细节见发行说明。

Eclipse JNoSQL

Eclipse JNoSQL 1.2.0 的第二个里程碑发布（Jakarta NoSQL规范的实现）带来了值得关注的变化，例如，新增的AutoApplyConverters类，用于扫描 Jakarta Persistence 的AttributeConverter接口实现，以支持在 JNoSQL 映射反射模块中自动应用转换器，以及在半结构化和键值存储实现中对 CDI 拦截器的支持，以便处理横切关注点。更多细节见发行说明。

Azul Payara

Azul Payara 7.3.0发布，包括 Community Edition 7.2026.8、Enterprise Edition 6.41.0 与 Enterprise Edition 5.90.0。除缺陷修复与组件升级外，三条发行线均带来了新特性：在所有 Azul Payara 版本中一致支持最新的gRPC 1.83.1，用于自定义和过滤访问日志记录内容的新机制，以及在控制台中改进的 Azul Payara Micro 访问日志格式显示。

此次发布还引入了 Jakarta Agentic AI 规范的初始实现。更多细节参见发行说明。

Open Liberty

Open Liberty 26.0.0.9 的beta版本发布，包含缺陷修复和新功能，例如，在mcpServer-1.0特性中对 MCP Java API（org.mcpjava:mcp-server-api:1.0.0）的支持，以及对 MCP 度量的更新，使 MBean 名称现在使用其自身的 JMX ObjectName键。后者为破坏性变更，要求开发者更新其 JMX 查询或脚本。

WildFly

WildFly 41.0.1 的发布带来缺陷修复、组件升级及若干重要变更，例如，根据 JEP 290（过滤传入的序列化数据（Filter Incoming Serialization Data））更新了过滤器，在应用的bin/jdk.serialFilter文件中加入了新的拒绝名单，以及升级到支持阻止解耦目的地的最新 Apache CFX 版本，作为降低服务器端请求伪造（Server Side Request Forgery，SSRF)风险的缓解措施。更多细节参见发行说明。

Quarkus

Quarkus 3.39.0发布，带来缺陷修复、依赖升级和两项新特性，也就是在 Quarkus 的TLS Certificate Registry扩展中支持后量子密码学（Post-Quantum Cryptography），以及由于无反射Jackson序列化器（reflection-free Jackson serializers）仍存在问题，撤销默认启用该特性的决定，不过该功能已有所稳定。更多细节见版本3.39.1和3.39.0的发行说明。

Quarkus 团队还发布了 Quarkus Flow 1.0.0 版本，该扩展实现了开发工作流规范（Open Workflow Specification）。该版本的新特性包括，可通过 YAML 或直接在 Java 代码中定义工作流的 Java DSL，与 LangChain4j 的 Agentic AI 编排，以及发出与消费云事件的能力。

Atmosphere

Atmosphere 4发布（用于 JVM 上的 AI 智能体实时引擎），现在包含了可移植的 AI 智能体组件。最近的两次维护性发布包含缺陷修复和新特性，例如，通过定义于AiConfig类的configureForAgent()方法对RUNTIME.md工作空间设置进行作用域限制，使工作空间为默认进程提供种子，以及在@ManagedService注解下添加 Spring Boot 低级处理器层。更多细节见版本4.0.69与4.0.68的发行说明。
