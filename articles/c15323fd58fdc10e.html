定位不是替代旗舰，而是承接高频Agent任务。GPT-6.1 Terra主打视觉理解、桌面操作与工具调用，速度约为前代三倍，单任务成本压到旗舰的九分之一。文章算了成本账，也点出权限与审计的隐患。

GPT-6.1 Terra 的产品定位很清楚：不是替代所有旗舰模型，而是用更低成本处理大量需要视觉理解、桌面操作和工具调用的工作。OpenAI 表示，它的任务执行速度超过 GPT-6 Astra 和 GPT-6.1 Sol 的 3 倍，最高推理强度下单任务成本约为 Claude Opus 5.5 的九分之一。

这类模型真正的价值，不在某一张跑分表，而在于能否把办公、财务、浏览器、代码和桌面软件操作变成稳定的自动化流程。模型越便宜，团队越可能把它放进更多任务；但调用规模扩大后，权限、审计和成本观测也必须同步升级。

不是最强模型，而是高频 Agent 的工作模型

GPT-6.1 Terra 面向希望降低自动化成本的企业和开发者。它重点强化视觉推理、电脑操作、事实准确率和编程能力，适合处理发票、技术图纸、桌面软件、表格和命令行任务。

模型路由可以按任务复杂度设计：

类型任务示例关注点
高频基础任务信息录入、分类、摘要、表格整理价格、速度和稳定性
桌面自动化跨应用填写、图纸读取、视频检查视觉理解、状态判断和可恢复性
代码 Agent修复布局、运行测试、修改仓库工具调用、成功率和回滚
高难度研究复杂软件工程、深度分析推理深度和最终准确率

Terra 适合放在第一层，旗舰模型则作为复杂任务的升级路径。这样做比让所有请求默认使用最高价模型更接近真实生产。

桌面操作能力，决定 Agent 能否脱离聊天窗口

在 Agents’ Last Exam 中，Terra 中等推理强度下的成绩比 GPT-5.6 Terra 高 15 个百分点，单任务成本约为上一代的三分之一。测试包含根据建筑图纸建立三维模型、记录电影镜头等复杂专业工作。

OSWorld 2.1 则测试模型使用桌面应用完成多步任务的能力。MMMU-Pro 用于评估视觉推理，Terra 在不同推理强度下均超过 GPT-5.6 Terra，并接近更高定位模型。

桌面 Agent 的难点不只是看懂屏幕，还要知道下一步操作是否安全。一个可靠流程应该记录：

  1. 当前应用、窗口和登录状态；
  2. 模型看到的页面或截图；
  3. 即将执行的点击、输入和文件操作；
  4. 操作后的页面变化和业务结果；
  5. 失败后的重试、回滚和人工接管。

否则，模型即使能完成一次演示，也不一定适合连续处理企业任务。

事实准确率提升，仍要保留证据链

OpenAI 通过内部基准测试评估模型的事实错误率。低推理强度下，Terra 错误率为 16.7%，GPT-5.6 Terra 为 53.6%；最高推理强度下，Terra 错误率进一步降至 4.3%。

这些数据能说明模型训练方向，但不能直接当作所有业务场景的总体准确率。企业接入时仍要要求：

  • 事实带来源、时间和字段路径；
  • 数字计算保留公式和中间值；
  • 无法确认时标记不确定，而不是补全；
  • 高风险结论交给人工或第二个模型复核；
  • 记录模型版本、提示词和工具调用历史。

对 Agent 来说，准确回答只是起点。只要它能写入数据库、发送邮件或触发流程，错误就会变成真实业务影响。

Terminal-Bench：编程能力需要放进预算里评估

Terminal-Bench 4.0 测试命令行编程 Agent 解决实际问题的能力，例如修复网页加载时发生的布局偏移。Terra 最高推理强度下成功完成 50.3% 的任务，上一代 GPT-5.6 Terra 为 21.5%。

OpenAI 仍建议使用 GPT-6.1 Sol 或 GPT-6 Astra 处理最难的编程任务。这种产品分工比较合理：Terra 负责规模化的中等复杂任务，旗舰模型负责高风险、高耦合和多轮失败任务。

代码 Agent 的成本不能只看 API 单价，还要考虑：

真实任务成本 = 输入 Token

+ 输出 Token

+ 工具调用

+ 失败重试

+ 人工返工

+ 测试和构建资源

一个低价模型如果经常生成错误补丁，最终账单可能高于单价更高但一次完成的模型。上线前应对真实仓库任务记录首轮成功率、端到端耗时、工具轮数和回滚次数。

每百万 Token 输入 1 美元

GPT-6.1 Terra 的标准 API 价格为：输入每百万 Token 1 美元，缓存输入每百万 Token 0.05 美元，输出每百万 Token 5 美元。相比 GPT-5.6 Terra 和 GPT-6.1 Sol，标准价格下降 50%；与 GPT-6 Astra 相比，输入和输出约为十分之一。

价格下降会扩大 Agent 的可用范围，但也会让团队更容易放任任务无限重试。建议设置项目级预算、单任务 Token 上限、每日调用上限和异常增长告警，并将缓存命中率纳入成本报表。

ChatGPT Work、Codex 与 API 接入

Terra 已面向 ChatGPT Plus、Pro、Enterprise 和 Edu 用户开放，可以在 ChatGPT Work 和 Codex 中使用；开发者可通过 gpt-6.1-terra 调用 API。

安全方面，OpenAI 表示 Terra 沿用了 GPT-6 Astra 的防护措施，并增强了抵御提示词注入和说明自身能力边界的能力。其网络安全能力达到 Preparedness Framework 的关键级门槛，因此企业接入时更要严格限制工具和网络权限。

国内团队如果需要将 Claude Code 等工具接入兼容 API，可通过 Code80 配置 endpoint；密钥、数据、审批、审计和生产权限仍由项目侧管理。

常见问题

GPT-6.1 Terra 是 OpenAI 当前最强模型吗？

不是。它的重点是速度、价格和高频 Agent 任务；最复杂的软件工程和深度研究仍可能需要 GPT-6.1 Sol 或 GPT-6 Astra。

Terra 适合直接操作企业桌面软件吗？

适合在受控环境中试点。必须限制登录状态、文件范围、网络访问和外部副作用，并记录完整操作轨迹。

如何判断低价模型是否真的省钱？

同时统计 Token、工具调用、失败重试、人工返工和测试资源。单价低但反复失败的模型，不一定带来更低的单任务成本。

什么时候应该升级到旗舰模型？

当任务涉及高风险生产变更、复杂跨文件重构、长程研究、连续失败或高价值决策时，可以根据路由规则升级，并保存升级原因与最终结果。

使用 Terra 时最重要的安全控制是什么？

使用最小权限、独立工作区、短期密钥、网络白名单、调用预算、审计日志和人工审批。模型速度越快，错误扩散也可能越快。
