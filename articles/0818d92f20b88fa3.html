11 月 9 日，AI 安全公司 Apiiro 发现 Claude Code 的设置文件正在公开 GitHub 仓库中泄露数据库密码、API 令牌和 root 登录信息等敏感信息。用户在审批 shell 命令时如果选择「Yes, and don’t ask again」，这条授权会作为规则写入本地的 .claude/settings.local.json 文件，规则有时以模式记录，但很多时候会原样写入命令本身，包括其中嵌入的敏感信息；Anthropic 文档称该文件会被加入开发者的全局 .gitignore，但这一设置不会体现在仓库层面，仓库被克隆到其他机器，或文件夹后来才变成仓库时，文件可能会被误传，Apiiro 还称 Claude Code 在很多情况下会在用户不介入时自行提交对该文件的修改。

Apiiro 本次共发现了超过 10 万个被上传到公开 GitHub 仓库的此类设置文件，其中约 1100 个、来自 63 个组织的文件含有密钥，这些密钥中有 215 个未被 gitleaks 和 TruffleHog 两款常用密钥扫描工具识别；文件被删除后，密钥仍可能留在原项目的分叉中。该问题最早在 2025 年 8 月就有人在 Claude Code 的错误报告中提出，相关报告均在 60 天无活动后被关闭。Claude Code 的 Boris Cherny 在 Hacker News 上表示，团队正在研究如何防止这一问题，同时称这类设置文件基本不应提交到 Git 仓库，相关情况似乎只出现在「文件被手动创建并提交」时；他建议用户使用 auto 模式和密钥扫描工具，团队也在考虑未来在 Claude Code 中内置密钥扫描。来源
